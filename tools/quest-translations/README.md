# Русские задания FTB Quests

Это инструмент подготовки исходников сборки. Он не запускается в игре, не меняет JAR и не требует особого кода в лаунчере. Нативный FTB Quests выбирает таблицу по языку Minecraft: `ru_ru` используется при русском языке, остальные языки сохраняют свои таблицы и нативный английский fallback.

## Состав

- `manual-ru.json` содержит проверенные переводы, точный fingerprint текущего английского значения и явные решения для названий проектов и технических строк.
- `author-ru.json` и `upstream-ru/` сохраняют отдельно захваченный авторский русский источник. Результат собственной генерации не считается новым авторским переводом.
- `ownership.json` связывает собственные записи с английским исходником и полученными байтами. Он также хранит исходный текст 38 старых подсказок на картинках.
- `inline-ru.json` задаёт только локализуемые поля `images[i].hover`. Их исходные английские подписи сохраняются в отдельном нативном языковом ресурсе.
- Единственная активная русская таблица — `config/ftbquests/quests/lang/ru_ru.snbt`. Исходные авторские русские файлы переносятся в `tools/quest-translations/upstream-ru/`; конкурирующих активных папочных таблиц нет.

Папка `tools` не входит в игровые корни `generate_manifest.py`. Снимки источников, переводческая история и тесты не доставляются в игровые экземпляры.

## Повторная подготовка текущего исходника

Из корня SOURCE-репозитория:

```text
python tools/quest-translations/prepare.py prepare --pack . --manual tools/quest-translations/manual-ru.json --inline-manual tools/quest-translations/inline-ru.json --ownership tools/quest-translations/ownership.json --author-cache tools/quest-translations/author-ru.json --report tools/quest-translations/last-report.json --apply
```

Повторный запуск с теми же входными данными сохраняет игровые файлы и provenance byte-for-byte. Без `--apply` команда формирует только план. Инструмент отказывается применять изменения к дереву с `saves` или `logs/latest.log`: рабочий игровой экземпляр не служит исходником.

## Обычное обновление авторской сборки

1. Получить и независимо проверить свежий официальный архив. Сохранить его распакованный `overrides` неизменным, включая отсутствие `ru_ru`, если автор его убрал.
2. Обычным инструментом обновления сначала импортировать новую базу SOURCE, её английские задания, моды и lock-файлы. Сохранить инструменты и provenance из этой папки, но не подменять ими свежие авторские русские файлы.
3. Захватить именно свежий источник до повторной генерации:

```text
python tools/quest-translations/prepare.py import-author --pack . --upstream PATH_TO_FRESH_UNTOUCHED_OVERRIDES --manual tools/quest-translations/manual-ru.json --inline-manual tools/quest-translations/inline-ru.json --ownership tools/quest-translations/ownership.json --author-cache tools/quest-translations/author-ru.json --report tools/quest-translations/last-report.json --apply
```

`--upstream` обязателен для явного импорта. Английские таблицы нового SOURCE должны точно совпадать с таблицами этого источника. Команда не импортирует моды и не ослабляет их SHA-lock: она обрабатывает только локализацию уже импортированной базы.

4. Проверить `refreshQueue` в отчёте. Новый настоящий авторский русский перевод имеет приоритет над нашими записями. Наша запись применяется лишь к отсутствующему/непереведённому авторскому полю и при совпадении английского fingerprint. Если EN изменился или ключ исчез, старая собственная запись пропускается. Для новых и изменённых заданий остаётся нативный английский fallback; обновление сборки продолжается.
5. Перевести очередь отдельно, обновить `englishFingerprint`, затем повторить подготовку. `preserve-brand` и `preserve-technical` — явные решения, а не фиктивные русские строки.

Если fresh-import пропущен, старый авторский cache тоже не переносится на изменившийся EN: инструмент сообщает об этом и оставляет английский fallback. Свежий импорт, где русского больше нет, очищает cache; прежние русские файлы не восстанавливаются автоматически.

Версия сборки и количество заданий не зашиты в инструмент. Не добавляйте `--require-complete` в обычный будущий update/publish: эта опция нужна только для явной проверки полного перевода конкретного подготовленного выпуска. Неизвестная будущая форма исходного SNBT фиксируется как `SKIPPED_UNSUPPORTED_SOURCE`, а не как общий запрет обновлений; исходные авторские данные сохраняются для отдельной адаптации инструмента.

## Нативные файлы после запуска игры

FTB Quests Lang Splitter может переименовать обработанные папочные файлы в `*_merged` и создать плоскую таблицу в INSTANCE. Подготовка не читает и не удаляет такие личные файлы. Для ATM10 путь заданий уже входит в `launcher/pack-owned.txt` (`config/ftbquests/quests/**`): обычная синхронизация доставит управляемую плоскую таблицу, предварительно сохранив отличающиеся локальные байты в `Personal/PackConflicts`. Не нужен новый whitelist или отдельная очистка из лаунчера.

## Проверка

```text
python -m unittest discover -s tools/quest-translations -p "test_*.py" -v
```

Проверяются приоритет нового авторского RU, точный EN fingerprint, новые/изменённые/удалённые ключи, повторный запуск, управляемая плоская таблица, защита собственного результата от ошибочного признания авторским, fresh-import с отсутствующим RU, атомарный откат, точные hover-spans и fallback старых подсказок.

Для текущей официальной 8.4 отдельно проверены настоящий SNBT/TranslationTable/FTB text parser из FTB Quests 2101.1.37 и Library 2101.1.39: 9222 текущих EN-ключа покрыты, 0 ошибок EN/RU text-parser, все 38 новых языковых alias дают те же английские styled components и правильные русские. Нативный AST подтверждает сохранность всех IDs, задач, наград, предметов, количеств, зависимостей и прочих полей за пределами 38 подсказок. Это проверка данных и парсеров; она не заменяет полный запуск клиента или проверку мира.
